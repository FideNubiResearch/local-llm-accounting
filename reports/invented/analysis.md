# Выдумки в итоговом прогоне: откуда они берутся

2026-11-19. Данные: `reports/rescore_final` (gemma4-12b q6, qwen3.5-4b q6, 1572 документа) и `reports/rescore_r1b`
(4 бит, P1b). Выдуманное = правильный ответ null, модель дала значение (исход FF). Доля = FF / (FF + TN) по ключам с
ответом null, основные поля. Разбор описательный, не входит в семейство проверок пререгистрации.

## 1. qwen3.5-4b: выдумки почти целиком в одном поле

| Конфигурация | Выдумано, все ключи | Без `subtotal` чеков | `subtotal` чеков |
|---|---|---|---|
| qwen3.5-4b q6 | 538 / 1197 = 44.9 % | 41 / 683 = **6.0 %** | 497 / 514 |
| qwen3.5-4b 4 бит | 625 / 1197 = 52.2 % | 116 / 683 = 17.0 % | 509 / 514 |
| gemma4-12b q6 | 17 / 1197 = 1.4 % | 5 / 683 = 0.7 % | 12 / 514 |
| gemma4-12b 4 бит | 15 / 1197 = 1.3 % | 5 / 683 = 0.7 % | 10 / 514 |

- 497 из 538 выдумок qwen3.5-4b q6 (92 %) — `subtotal` чека, которого на странице нет. 481 из них — в синтетических
  чеках (`synthetic_receipts`). Остальные поля вместе дают 41.
- **«Языковой» эффект (de/fr/it 66–75 % против 0 % у es/nl/pl/pt) — артефакт типа документа:** чеки есть только в
  de, fr, it, en, id, ko (по 160 в de, fr, it), а es, nl, pl, pt состоят только из счетов, где `subtotal` не спрашивается.
  Сравнивать языки по доле выдумок без учёта типа документа нельзя.
- Что именно модель пишет вместо null (497 случаев): копия итога — 165 (33 %); «итог минус налог» — 120 (24 %);
  другое число — 134 (27 %); итог/налог не разобрать — 78 (16 %). То есть модель в основном **вычисляет или
  угадывает** недостающую строку, хотя P1b прямо говорит «не копируй итог в subtotal».
- Лучше с 6 битами, чем с 4: 17.0 % → 6.0 % без `subtotal`, но `subtotal` остаётся выдуманным почти всегда.

Вопрос владельцу (политика скорера): вычисляемый `subtotal` (итог − налог) на чеке, где строки нет, считать
выдумкой (как сейчас) или допустимым выводом? От ответа зависит, насколько «плоха» модель на этом поле; без
`subtotal` qwen3.5-4b q6 выдумывает 6.0 %, gemma 0.7 %.

## 2. gemma4-12b q6 на реальных документах: рост выдумок с 0 до 8

| | Ключей null | Выдумано |
|---|---|---|
| 4 бит, реальные документы | 133 | 0 |
| q6, реальные документы | 133 | 8 (6.0 %) |
| q6, сгенерированные | 1064 | 9 (0.8 %); у 4 бит 15 (1.4 %) |

- Восемь новых выдумок: `subtotal` чека — 5 (en 3, id 2), счета — 3 (`invoice_number`, `purchase_order`,
  `seller_vat_id`, по одному). Парный тест на реальных null-ключах: 8 в худшую сторону, 0 в лучшую, точный знаковый
  p = 0.0078 (без поправки на множественность: описательно). Эффект реальный, но на 133 ключах абсолютно малый.
- Цифра «66.7 % выдуманного у реальных pt» в предыдущем отчёте — 2 выдумки из 3 ключей null, это шум.
- Точность значений на реальных документах у q6 выше, чем у 4 бит, но неравномерно: pt 79.2 → 84.7,
  korie 92.1 → 98.4, zugferd 95.9 → 97.4, wildreceipt 97.5 → 98.7; ниже у sroie 98.5 → 95.6 и cord 94.6 → 93.7
  (значений 63–736 на источник, интервалы широкие).
- Общий вывод: на реальных документах q6 даёт больше верных значений и чуть больше выдумок. Чтобы отделить это от
  шума, нужно больше реальных документов с ответом null.

## 3. Что делать

1. Решить политику по вычисляемому `subtotal` (см. выше). Если считать допустимым, пересчитать итог без
   прогона моделей (`harness.report`), число выдумок qwen3.5-4b упадёт.
2. Для сравнения выдумок между моделями и языками всегда показывать долю с `subtotal` чеков и без.
3. Не интерпретировать «выдумки по языку» без разбивки по типу документа.
