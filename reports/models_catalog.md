**Gemma 4 E4B.** [The official card](https://huggingface.co/google/gemma-4-E4B-it/blob/4ecc2ba63bcac23ba4a767fc87025b1450f84c9c/README.md) states ≈4.5B effective / ≈8B with embeddings; the weights are licensed Apache-2.0, official text — [Apache License 2.0](https://ai.google.dev/gemma/apache_2). The [MLX conversion card](https://huggingface.co/mlx-community/gemma-4-e4b-it-4bit/blob/475b9088d29754a3379866cf5aeb6b41acd313c2/README.md) says `license: gemma`: a metadata contradiction, so the licence in the table is based on upstream. [Processor](https://huggingface.co/mlx-community/gemma-4-e4b-it-4bit/blob/475b9088d29754a3379866cf5aeb6b41acd313c2/processor_config.json) sets 280 visual tokens; [template](https://huggingface.co/mlx-community/gemma-4-e4b-it-4bit/blob/475b9088d29754a3379866cf5aeb6b41acd313c2/chat_template.jinja) controls thinking; budgets 70/140/280/560/1120 are also supported by [mlx_vlm/models/gemma4/processing_gemma4.py](https://github.com/Neywa-Labs/mlx-vlm/blob/8c061ef516e7f8b584c0d5b64f26b50d5806303b/mlx_vlm/models/gemma4/processing_gemma4.py#L32); the authors recommend larger budgets for small text, not the forced 224×224 from the `size` field.

**Gemma 4 12B.** This is exactly [12B Unified IT](https://huggingface.co/google/gemma-4-12B-it/blob/43c9d014b231474fa7212dbb48a762566c2b255d/README.md) with `model_type=gemma4_unified`, not Gemma 3 12B; Apache-2.0 is confirmed by the official card. The Variable Image Resolution section of the official card recommends larger budgets for OCR; no exact recommended A4 size found.

**MiniCPM-V 4.5 8B.** The `minicpmv` type, slicing and the thinking switch are confirmed by [the official card](https://huggingface.co/openbmb/MiniCPM-V-4_5/blob/14a2004908140699317e2109e90573c1e6323c36/README.md), [config](https://huggingface.co/openbmb/MiniCPM-V-4_5/blob/14a2004908140699317e2109e90573c1e6323c36/config.json) and [processor](https://huggingface.co/openbmb/MiniCPM-V-4_5/blob/14a2004908140699317e2109e90573c1e6323c36/preprocessor_config.json). [The API of the «4bit» repository found](https://huggingface.co/api/models/ekryski/MiniCPM-V-4_5-4bit/revision/67c26b3aa5a6a03cc642d1c2d903a32ebfba9d4e?blobs=true) shows a single `.gitattributes`; these are not ready weights. [mlx_vlm/utils.py](https://github.com/Neywa-Labs/mlx-vlm/blob/8c061ef516e7f8b584c0d5b64f26b50d5806303b/mlx_vlm/utils.py#L42) has no `minicpmv` alias, [the 0.7.10 tree](https://api.github.com/repos/Neywa-Labs/mlx-vlm/git/trees/8c061ef516e7f8b584c0d5b64f26b50d5806303b?recursive=1) has no module of this type; a check of [0.7.12](https://api.github.com/repos/Neywa-Labs/mlx-vlm/git/trees/7230940302cbe602054650f18a2f77db945bc57a?recursive=1) and its [utils.py](https://github.com/Neywa-Labs/mlx-vlm/blob/7230940302cbe602054650f18a2f77db945bc57a/mlx_vlm/utils.py) found no support for this type either. No minimum supporting version found; V 4.6/o 4.5 do not replace the candidate from the plan.

**InternVL3.5 8B.** [An HF search for the exact name with filter=mlx](https://huggingface.co/api/models?search=InternVL3_5-8B&filter=mlx&limit=100) returned `[]`; name variants with a dot and the general MLX list of InternVL3 were also checked: no ready 3.5 8B found. **GLM-4.1V 9B.** Chosen: [GLM-4.1V-9B-Thinking](https://huggingface.co/zai-org/GLM-4.1V-9B-Thinking/blob/3c1471e51dc811b589d4d12b1c1c7c1c941267c2/README.md), MIT is stated in the header of the official card; 4K maximum is a stated capability, not a recommendation to fix A4 at 4K. Exact pixel limits — [processor](https://huggingface.co/mlx-community/GLM-4.1V-9B-Thinking-4bit/blob/74017f107021b8ade1aa0f1f5422e0a0dee0e86c/preprocessor_config.json), the absence of a thinking switch — [template](https://huggingface.co/mlx-community/GLM-4.1V-9B-Thinking-4bit/blob/74017f107021b8ade1aa0f1f5422e0a0dee0e86c/chat_template.jinja); `enable_thinking=False` should not be considered a proven way to disable it. [A search for MLX variants](https://huggingface.co/api/models?search=GLM-4.1V-9B-Thinking&filter=mlx&limit=100) found 4/5/8-bit; 6-bit not found. Thinking must be accounted for separately when limiting the context and getting clean JSON.

**lift 9B.** [The oQ4 card](https://huggingface.co/mlx-community/lift-oQ4/blob/491aabd0050652b6a363295dd57cedb9303a693c/README.md) describes mixed quantisation at ≈4.6 bpw; [config](https://huggingface.co/mlx-community/lift-oQ4/blob/491aabd0050652b6a363295dd57cedb9303a693c/config.json) has a general `bits=4` and overrides up to 5 bits: it cannot be labelled uniform 4-bit in a quantisation comparison. [The weight licence](https://huggingface.co/datalab-to/lift/blob/221e0fcecfb3f557ca123e5a6e3452d459c25d90/LICENSE) — **AI PUBS OPEN RAIL-M LICENSE (MODIFIED)**: Attachment A 2a–b restricts organisations with revenue/funding >$5M, with a personal/research exception; 2c forbids use by competitors of the licensor's products/services and has no such exception; §§7–8 require attribution and Share-a-Like, including Output. This is a licence with commercial-use restrictions, not plain Apache-2.0 and not strictly «NC only»; [processor](https://huggingface.co/mlx-community/lift-oQ4/blob/491aabd0050652b6a363295dd57cedb9303a693c/preprocessor_config.json)/[template](https://huggingface.co/mlx-community/lift-oQ4/blob/491aabd0050652b6a363295dd57cedb9303a693c/chat_template.jinja) give no separate A4 recommendation or thinking switch, and the card's Notes section describes the EOS fix to `[248044, 248046]`.

**NuExtract3 4B.** The official NuMind conversion was chosen, not only a community bf16; [the 4bits card](https://huggingface.co/numind/NuExtract3-mlx-4bits/blob/29c38269f94054282bf9ea97a20dfc6bb8bbefea/README.md) and [config](https://huggingface.co/numind/NuExtract3-mlx-4bits/blob/29c38269f94054282bf9ea97a20dfc6bb8bbefea/config.json) confirm affine 4-bit/group_size=64, weight licence — [Apache-2.0](https://huggingface.co/numind/NuExtract3/blob/c99dc8f5641b866aa0192b6ea78f84bf9f3535f1/LICENSE). [The authors' recommendation](https://huggingface.co/numind/NuExtract3/blob/c99dc8f5641b866aa0192b6ea78f84bf9f3535f1/README.md) is to start without reasoning; in the [template](https://huggingface.co/numind/NuExtract3-mlx-4bits/blob/29c38269f94054282bf9ea97a20dfc6bb8bbefea/chat_template.jinja) the default mode is `content`, and a `template` switches it to `structured`: a template of leaf types is required, not a direct JSON Schema. [Processor](https://huggingface.co/numind/NuExtract3-mlx-4bits/blob/29c38269f94054282bf9ea97a20dfc6bb8bbefea/processor_config.json) sets the pixel range; no recommended resolution for A4 specifically found; a prompt adapter to this contract is needed before a run, otherwise the extraction mode is not ensured.

The numbers can be re-checked without downloading weights (substitute repo/SHA from the row):

```bash
curl -fsSL 'https://huggingface.co/api/models/REPO/revision/SHA?blobs=true' |
python3 -c 'import json,sys; d=json.load(sys.stdin); s=[x for x in d["siblings"] if x["rfilename"].endswith(".safetensors")]; print("sha:",d["sha"]); print(*[(x["rfilename"],x["size"]) for x in s],sep="\n"); n=sum(x["size"] for x in s); print("sum_bytes:",n,"GB:",n/1e9,"GiB:",n/2**30)'
```

**Recommended for the first round (all at 4 bits; the order is preliminary, without quality measurements)**

1. **Qwen3-VL 4B Instruct** — already working starting point, minimal organisational risk and a large estimated memory margin.
2. **Qwen3-VL 8B Instruct** — a size comparison within the same family at an estimated ≈7.761 GB including the 2 GB allowance.
3. **Qwen3.5 4B** — a modern alternative architecture with practically the same weight size as the original 4B.
4. **Qwen3.5 9B** — a control for the effect of size within Qwen3.5 at an estimated ≈7.950 GB.
5. **Gemma 4 E4B IT** — another family and vision path with a moderate weight size; mind the licence discrepancy on the conversion card.
6. **NuExtract3 4B** — a specialised extractor on the same Qwen3.5 4B base, for comparison with the VLMs once its typed template is wired in.
