| Режим | Что меняется | Прогоны |

| P2b | промпт = P1b + цитата из документа к каждому значению | 3 |

| экстракторы | NuExtract3 4B, lift 9B (после адаптера промпта; отдельная поправка с их настройками до запуска) | 2 |

## 4. Метрики

Как в harness/prompt_compare.py. Основные поля = все, кроме payment_method (отдельная строка).
- Первичная: F1 основных полей (precision = TP/(TP+WV+FF), recall = TP/(TP+WV+FN)).
- Вторичные: доля выдуманного FF/(FF+TN), она же без subtotal чеков; доля документов, где верны все основные поля;
  JSON valid; секунд на документ (медиана); пик памяти; своп (runs/system.jsonl).

## 5. Сравнение и решение

- Каждый режим сравнивается с базой **той же модели на тех же ключах** (doc, field): лучше = неверно в базе и верно в
  режиме, хуже = наоборот; точный знаковый тест (McNemar).
- Поправка на множественность: Холм по всем сравнениям раунда 2 (режим × модель), α = 0,05.
- Режим «лучше базы» для модели: лучше − хуже > 0 и p по Холму < 0,05. «Хуже» — симметрично. Иначе — «без разницы».
- Выдумки оцениваются отдельно тем же парным тестом только по ключам с ответом null.
- Квантование и 27B оцениваются ещё и по цене: секунды на документ и пик памяти рядом с F1; «не помещается» —
  тоже результат (раздел 6).

**Лучшая конфигурация** = (модель, режим) с наибольшим F1 на выборке среди тех, что не хуже своей базы; при разнице
F1 < 0,3 п. — меньше выдуманного, затем быстрее. Она и qwen3.5-4b в том же режиме (вопрос «насколько хуже вдвое
более быстрая модель») прогоняются на всём final/ — это итоговые цифры исследования.

## 6. Остановка и пропуск

- Smoke: JSON valid < 50 % или точность ≈ 0 на первых 20 документах → конфигурация не идёт в основной прогон,
  причина записывается (как в 00-plan.md 8.1).
- Память: своп растёт больше чем на 2 ГБ за прогон smoke или секунд на документ > 4× от 4-битной версии той же
  модели → конфигурация пропускается, записывается как «не годится для Mac mini 16 ГБ».
- Модель не загрузилась / OOM → пропуск с причиной.
